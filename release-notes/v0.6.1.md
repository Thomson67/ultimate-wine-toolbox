# Ultimate Wine Toolbox v0.6.1

## Français

### Création et mise à jour WSquashFS

- Le bouton B / Retour permet de remonter entre les étapes au lieu de revenir systématiquement au menu principal. L’abandon reste une action distincte ; les déplacements de données déjà réalisés ne sont pas rejoués. Les mises à jour préparées restent reprenables.
- Lors de la création, une sauvegarde déjà présente peut être conservée : elle reste intacte et les données du test sont écartées, sans copie supplémentaire. Pour les fichiers individuels ou user.reg, les fichiers attendus doivent déjà exister dans la destination.
- Détection des sauvegardes dans les sous-dossiers du jeu, même avec un nom quelconque. Le dossier de l’exécutable et ses parents restent exclus du choix SAVEDIR ; les fichiers placés à côté de l’exécutable relèvent de SAVEFILES.
- Scoring amélioré : noms de fichiers contenant sav, slot ou user et extensions de sauvegarde favorisés ; cache dans un nom de fichier ou de dossier pénalisé. Les fichiers de cache ne comptent pas comme indices positifs, même avec un nom ou une extension évoquant une sauvegarde.
- Les dossiers contenant uniquement des fichiers clairement temporaires, comme .log ou .tmp, sont écartés. Les fichiers .txt et sans extension restent des candidats possibles.
- Les propositions moins bien classées sont regroupées dans « Voir plus d’emplacements possibles ». Les ex æquo restent ensemble.
- Documentation intégrée actualisée en français et en anglais.

### Runners

- Correction de la sélection des archives GE-Proton classiques pour les premières releases 11.x : reconnaissance des anciens noms sans suffixe d’architecture et préférence pour les archives x86_64 explicites. Les archives ARM ne sont plus retenues par défaut.
- Somme de contrôle associée à l’archive sélectionnée. Le contenu de files/ continue d’être remonté à la racine du runner.

## English

### WSquashFS creation and updates

- B / Back navigates between steps instead of always returning to the main menu. Abandoning remains a separate action; completed data transfers are not repeated. Prepared updates remain resumable.
- During creation, existing saves can be retained unchanged while test data is discarded without an extra copy. For individual files or user.reg, the required files must already exist at the destination.
- Save detection now includes arbitrarily named game subdirectories. The executable directory and its ancestors remain excluded from SAVEDIR selection; saves beside the executable use SAVEFILES.
- Improved scoring: filenames containing sav, slot or user and save-related extensions rank higher; cache in filenames or directory names lowers scores. Cache files do not provide positive evidence even with save-like names or extensions.
- Folders containing only clearly temporary files, such as .log or .tmp, are excluded. Text and extensionless files remain possible candidates.
- Lower-ranked suggestions appear under “See more possible locations”, with tied scores kept together.
- Updated French and English offline documentation.

### Runners

- Fixed classic GE-Proton asset selection for early 11.x releases: recognize older names without an architecture suffix and prefer explicit x86_64 archives. ARM archives are no longer selected as a fallback.
- Checksums follow the selected archive. Contents of files/ are still moved to the runner root.
