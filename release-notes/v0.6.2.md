# Ultimate Wine Toolbox v0.6.2

## Français

### Retour automatique dans la Toolbox

- Correction du retour après les essais de jeux sous Batocera v44 avec Ports regroupé. Les parcours de création et de mise à jour WSquashFS, ReShade et AntiMicroX partagent le même mécanisme de retour par EmulationStation.
- Un lanceur technique caché sous Ports reprend la commande native et le profil Pad2Key de la Toolbox. Le regroupement des autres systèmes reste inchangé. Le lancement habituel est conservé lorsque Ports n'est pas regroupé.
- Le retour attend la libération de l'ancien lanceur et confirme la consommation de la demande de reprise. Si ES est occupé ou indisponible, la reprise reste disponible à la prochaine ouverture manuelle.
- Correction des retours successifs après réécriture du gamelist.xml par ES : un marqueur séparé identifie le lanceur, les installations déjà touchées sont reconnues et les statistiques ES sont conservées.

### Mise à jour WSquashFS

- Ajout de « Mettre à jour un autre WSquashFS » à la fin du parcours, en conservant l'accès à la création d'une nouvelle archive.
- Le matching exact reste prioritaire. En l'absence de correspondance exacte, les noms partageant le premier mot sont proposés ; les autres choix et la sélection manuelle restent disponibles.
- Possibilité de partir d'un préfixe .wine existant, réutilisé sur place sans extraction. L'archive finale reprend son nom ; les choix de création ou de remplacement dépendent de la présence d'un WSquashFS existant.
- Avec mergerfs, un déplacement qui échoue avec EXDEV peut utiliser les chemins physiques des différentes branches, sans recopier les fichiers du jeu. Les déplacements sont journalisés et annulés en cas d'échec ; une récupération manuelle reste nécessaire si le retour en arrière est incomplet.
- Les erreurs d'extraction consignent la commande, les sorties, le code de retour et les limites de fichiers ouverts. La limite du processus d'extraction est relevée lorsque le système le permet.

### Vérification d'intégrité

- Correction de la détection du contrôle complet avec les versions récentes d'unsquashfs dont -help affiche uniquement un résumé. L'aide complète est consultée si nécessaire, tout en conservant la détection des anciennes versions.
- Une option réellement absente reste signalée comme non prise en charge ; une erreur de lecture ne devient pas un contrôle réussi.

La création WSquashFS reste en bêta. Le support MangoHud des systèmes Wine custom n'est pas inclus dans cette version.

## English

### Automatic Toolbox return

- Fixed return after game tests on Batocera v44 with grouped Ports. WSquashFS creation and update, ReShade and AntiMicroX workflows now share the same EmulationStation return mechanism.
- A hidden technical launcher under Ports reuses the native launch command and the Toolbox Pad2Key profile. Other systems remain grouped. The usual launcher remains in use when Ports is not grouped.
- Return waits for the previous launcher to exit and confirms that the resume request was consumed. If ES is busy or unavailable, recovery remains available on the next manual Toolbox opening.
- Fixed successive returns after ES rewrites gamelist.xml: a separate ownership marker identifies the launcher, affected existing installations are recognized and ES statistics are preserved.

### WSquashFS updates

- Added “Update another WSquashFS” after completion while retaining access to new archive creation.
- Exact matching remains the first choice. First-word suggestions appear only when no exact match exists; other choices and manual browsing remain available.
- Existing .wine prefixes can be reused in place without extraction. The final archive uses the same base name, with creation or replacement choices depending on whether a WSquashFS already exists.
- When a mergerfs move fails with EXDEV, physical paths on each branch can be used without copying game data. Moves are journaled and rolled back on failure; manual recovery remains necessary if rollback is incomplete.
- Extraction failures record the command, output, exit code and open-file limits. The extraction process limit is raised where permitted by the system.

### Integrity checks

- Fixed full-check capability detection for recent unsquashfs versions whose -help only displays a summary. Full help is consulted when needed while retaining compatibility with older help output.
- A genuinely missing option is still reported as unsupported; read failures are never treated as successful checks.

WSquashFS creation remains in beta. MangoHud support for custom Wine systems is not included in this release.
