PURPOSE
Create a .wsquashfs archive with external saves in /userdata/saves/windows/<game name>, stored separately from the archive.

COMPATIBILITY
Native SAVEDIR= support requires Batocera v42 or later. An optional experimental boot patch for v41 is available in WSquashFS Management. V40 remains excluded.

1. SELECT THE GAME
Open the WSquashFS creation entry and select a folder directly inside /userdata/roms/windows.
You can reuse an existing .wine prefix. For a game folder that needs preparation, choose a prefix template. The default template can be downloaded if needed.
Game data is moved into the prefix: read the confirmation before continuing.

2. SELECT THE EXECUTABLE AND RUNNER
Choose the .exe that starts the game.
The system default runner is offered first. Custom runners follow, with UMU runners listed first.

3. TEST AND CREATE A SAVE
The game launches for testing. Play long enough to create a real save, then close the game.
The Toolbox reopens and asks you to confirm the launch. If there is a problem, retry, change the runner or adjust the available options.
If the controller does not work, select enable HIDRAW and relaunch. DXVK, FPS limit, large address awareness and virtual desktop options can also be adjusted for this game.

4. SELECT THE SAVE LOCATION
B / Back returns to the preceding screen. Abandoning the operation remains a separate action. After externalization, going back does not repeat data transfers.
Review the detected locations and inspect their contents to confirm where the save is stored. Game subdirectories are also checked for SAVEDIR, even with arbitrary names. Filenames containing sav, slot or user and save-related extensions rank higher. Cache in a directory or filename lowers the score; cache files do not count as positive evidence even when they contain user or use a .sav extension. Folders containing only temporary files such as .log or .tmp are ignored; .txt and extensionless files remain possible candidates. Saves beside the executable belong to individual-file selection (SAVEFILES), rather than externalizing the whole game directory.
For long lists, See more possible locations groups lower-scoring suggestions; tied scores stay together.
Manual search opens a folder picker so you can browse the prefix and choose another folder.
Select the game's own save folder, rather than a general folder containing unrelated data.
If nothing is detected, relaunch to create a save, search manually, use user.reg if the game stores progress there, or leave creation.
Using user.reg preserves the whole file, which may also contain Wine settings.

5. EXTERNALIZE AND COMPRESS
Confirm externalization to /userdata/saves/windows/<game name>. If saves already exist at that destination, choose to back them up, replace them or keep the existing save. Keeping existing saves discards test data without creating an extra copy. For individual files or registry saves, the required files must already exist in the retained destination.
The Toolbox prepares autorun.cmd with SAVEDIR= and, for registry saves, SAVEFILES=user.reg.
Compress immediately or keep the prepared prefix for later.
Before compression, keep the proposed name or choose another name. If the archive already exists, back it up and replace it, replace it directly, or create an archive under another name.
When the final archive is renamed, saves are copied under the new name and game settings are transferred. Original saves are preserved.
After compression, run the proposed quick check or skip it. Cancel does not finalize the new archive. Deleting the source prefix is offered after successful creation.

6. CHECK THE RESULT
Launch the new .wsquashfs and confirm that your progress is restored.
The integrity entry in WSquashFS management can check the structure or read and decompress all data without extracting files to disk. It does not check whether the game works.
Simple .wine compression in this menu does not by itself perform the save externalization workflow described here.
