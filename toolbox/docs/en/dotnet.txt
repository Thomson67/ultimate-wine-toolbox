.NET: WINE MONO OR MICROSOFT

Wine Mono is an alternative to .NET Framework up to 4.8.1. It does not replace modern .NET runtimes such as .NET 6 or 8. It may satisfy launchers, configuration tools and games; some applications need Microsoft’s framework.

BATOCERA ALREADY PROVIDES MONO

Batocera v41 sources package shared Mono 9.3.0 with Wine TKG. v43.1 sources package shared Mono 10.4.0 under /usr/share/wine. Custom builds and runners may differ. A shared directory does not prove that the prefix uses it. Wine may also register Mono inside the prefix.

Diagnostics distinguish Mono, Microsoft .NET evidence, mixed state, unidentified traces and no identified components. An NDP Release value alone cannot identify Microsoft: Mono may create the same keys. Detection is not an execution test.

WORKFLOW

After testing the game, open .NET from the result menu (creation or update). In creation it is also available from Winetricks components.

Install / update Mono downloads the official stable MSI, verifies its SHA-256, and installs inside a local copy of the working prefix. The x86 package also supports x86-64. It does not update Batocera’s shared runtime.

Replace Mono with .NET Framework 4.8 uses Winetricks remove_mono followed by dotnet48 through the selected runner. Mixed or uncertain states are refused, not forced. Already identified Microsoft installations are not automatically reinstalled. Compatibility depends on the runner and prefix architecture; inspect the log on failure.

Proton/UMU may reapply its own Mono version. Prefer bundled Mono unless a game has a confirmed need, then test a second launch. Latest Mono may not suit an older runner.

SAFETY COPIES

Before installation, a prefix copy is stored under the Toolbox’s backups/dotnet directory. The main game directory identified from autorun is excluded; symlinks are copied without following targets, including external saves. The source archive remains intact. Do not delete the game directory when restoring: the copy does not contain it. The log records the exact backup path. There is no automatic rollback on failure.

Experimental until installation, relaunch and archive persistence have been validated on Batocera.

LOCAL INSTALLATION AND RECOVERY

Installers run in a copy under state/dotnet-work, outside the ROM directory. Game files are not copied. Local storage must support the atomic file/directory exchange used by some Wine TKG builds; this is tested before installation. Set UWT_DOTNET_WORK_ROOT to use another local directory if needed.

TKG .REPARSE_POINT metadata is preserved without traversal or dereferencing. Its ${WINEPREFIX} anchors are relocated for staging and final publication. Shared runtime and runner DLL files remain intact.

Only a successful, verified result is transferred to the working prefix. Installer failure preserves the original prefix and retains the local copy for log inspection. Mono MSI also writes windows/temp/uwt-mono-install.log inside that copy. Transfer errors roll back previously replaced entries; if rollback fails, recovery files are retained and their location is logged. Allow space for the backup, local copy and transfer.

Restore a safety copy returns to an earlier state. Copies are sorted oldest first: after multiple incomplete installations, choose one predating the first attempt. Game files and external save targets stay in place; other prefix files revert to the selected date. The current state is backed up before restoring.

UMU RUNNERS

When replacing Mono with Microsoft .NET, a temporary Winetricks copy removes each Mono GUID separately and clears NDP v3.5/v4 keys in both 32-bit and 64-bit registry views when Mono is detected. This handles multiple Mono entries and GE-Proton compatibility traces that can make setup report .NET as already installed. Batocera's Winetricks remains unchanged. Unrecognized script versions are rejected.

.NET operations use the selected runner’s underlying Wine engine directly, including setup EXEs. They do not launch these installers as UMU/Proton games: regedit, winecfg, setup EXEs and wineserver must share one engine and local prefix. Normal game launches still use UMU. Success also requires the Winetricks dotnet48 marker; .NET 4.0 alone is insufficient.

INSTALLER WINDOWS DURING TESTING

.NET tests are interactive: no Winetricks -q or MSI /qn. Wine Mono / Microsoft windows are shown and the terminal displays live logs. Follow setup screens without requesting an immediate Wine restart. Winetricks uses zenity/kdialog for questions if available, otherwise stdin stays available in the terminal. Use Alt+Tab for hidden windows. Terminal fullscreen is temporarily removed and restored if wmctrl and xprop are available; saved preferences are unchanged.

The soft open-file limit is raised to 65536 for the installer process and children only when lower and allowed by the existing hard limit. Hard limits and system settings are unchanged. Old and effective limits are logged. This addresses low inherited limits but does not guarantee runner/.NET compatibility.
