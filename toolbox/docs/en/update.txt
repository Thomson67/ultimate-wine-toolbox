UPDATE A WSQUASHFS

PURPOSE
Replace the game files with a newer version while retaining launch settings and saves. This workflow supports archives containing a Wine prefix; .pc archives without a prefix are not supported.

1. PREPARE THE NEW VERSION
In WSquashFS Management, choose Update a WSquashFS. Select the archive and the folder containing the new game files directly. The source folder is moved into the working prefix and will no longer remain at its original location. Allow space for extraction and recompression.

2. TEST THE GAME
The first test keeps the archive’s executable and arguments. Check launch, controllers, loading progress and saving again. On return, Review / change the game executable lets you correct the launch command. Original start.bat files are preserved. The old game folder remains in .bak until launch is validated.

3. CONFIRM SAVES
Keep existing save rules or select another location. Tests normally use a separate copy of the saves. Exception: a link to the root /userdata/saves/windows keeps its target and directly uses shared saves.

“Inspect existing saves” shows the path, filenames, sizes and dates in the existing Batocera save folder without modifying it. The test prefix contents remain separately accessible. Back from the final archive choice returns to save review before preparation. Resuming after a compression failure also allows save review; retaining the same existing rules reuses the prepared copy without repeating its transfer.

Inspection is also available for legacy save links. When a link targets the shared saves/windows root, select the game's subfolder to inspect. Back from save selection returns to game settings; the operation remains resumable if left at this step. Relaunching restores test-save links before starting the game, while preserving the special case of legacy links targeting the shared root.

4. COMPRESS AND FINALIZE
Choose to back up the old archive before replacement or replace it directly. After compression, run the proposed full check or skip it. Cancel at this stage does not replace the archive. Skipped checks can be run later from WSquashFS Management.

An unfinished operation can be resumed from the menu. Errors identify the retained prefix and the log to inspect. After success, old game bottles are cleaned and removing the working prefix is offered. Finally, launch the new WSquashFS and verify your progress.

Exact names have priority. Without an exact match, suggestions rank by the number of consecutive shared words at the start of the title. Verify these suggestions; other folders and Browse remain available. After success, “Update another WSquashFS” starts the next update.

With mergerfs, if direct renaming fails with EXDEV, the Toolbox attempts to rename each physical source directory within its own branch without copying game files. Paths are recorded in the report and preparation manifest; moves are rolled back on failure. If rollback is incomplete, retain the prefix, .bak and report for recovery.

STARTING FROM AN EXISTING .WINE
The initial list also offers .wine prefixes containing system.reg and autorun.cmd. They are reused in place without deletion or extraction. Then select the updated game directory. The final archive uses the same basename with .wsquashfs: existing archives offer the usual backup/replacement choices; otherwise, creation is offered. An unresolved old .bak directory must be addressed before restarting.

GROUPED PORTS COMPATIBILITY
If the ES API skips the Ports group, return uses an owned technical launcher in the uwt_return child system, itself grouped under Ports. The Toolbox creates only es_systems_uwt_return.cfg and its runtime/es-return-proxy assets. The launcher and folder are marked hidden. The native Ports command and Toolbox Pad2Key profile are reused. The global ports.ungroup preference is not modified. If ungrouping was enabled for a test, restore the desired grouping through ES collection settings.

With mergerfs, free space is checked per disk and a suitable physical archive location is offered before compression. Total free space does not guarantee one archive fits on a disk. Keep the Toolbox open during compression, verification and finalization: closing it interrupts workers and retains recovery state.

SAVE-DATA BACKUP COPIES
Keeping links or save rules preserves locations, but tested progression may replace active save files during publication. The previous folder is renamed <name>.backup-<date>. This permanent copy differs from temporary test saves, which are cleaned after success.

At the end of a successful update, choose whether to delete save-data backup copies created by that operation. No keeps them; Yes removes only the listed verified copies. Active saves and any old WSquashFS archive backup are kept. The choice persists if finalization is resumed. Changed or undeletable backups are kept with a warning; optional cleanup does not undo the successful update.

Earlier updates’ backups and copies explicitly created for a destination conflict are not removed by this choice. Old pending operations lacking a full backup record retain their copies. No global deletion of .backup-* folders occurs.

LINKS ALREADY PRESENT IN THE NEW VERSION
If the source directory contains links at save locations already known by the existing configuration, the Toolbox displays their current targets and the configuration targets, then offers to replace them. Links are restored in the working prefix with the usual test redirections. Declining stops preparation before the source directory is moved. Old target folders remain untouched and their progress is not imported automatically. External links without a known matching save location remain rejected.
